# SIGNAL PRO — Telegram Mini App

تطبيق موبايل (Mini App) مبني بـ **React + Vite + Tailwind CSS + Framer Motion**.
صفحة واحدة يعلوها هيدر ثابت، وكل الأقسام الفرعية تُفتح في نوافذ عائمة من
أيقونتَي الهيدر.

## التشغيل

```bash
npm install
npm run dev
```

## البناء للنشر

```bash
npm run build
```

يُنتج مجلد `dist/` — ارفعه على أي استضافة ثابتة (Vercel / Netlify / Cloudflare Pages)
ثم اربط الرابط مع BotFather عبر `/newapp`.

    ├── LiveSignals.jsx         ← الصفقات المموّهة (صفقة جديدة كل ٣٠ ثانية)
    ├── ResultsFeed.jsx         ← ٢٠ صفقة في حاوية تُمرَّر (تتجدّد كل ٢٠ ثانية)
    ├── PlatformsMarquee.jsx    ← الشريط المتحرك للمنصات
    ├── HowItWorks.jsx          ← مربّع شرح آلية التحليل
    ├── Dialog.jsx              ← هيكل النافذة العائمة (يُبنى عليه الباقي)

## ترتيب الصفحة

1. **الهيدر** — أيقونة الملف الشخصي (يمين) + الهوية (وسط) + المزيد (يسار)
2. **الصفقات المباشرة** المموّهة + زر "عرض الصفقات"
3. **نتائج الصفقات السابقة** — ملخّص وثلاث صفقات + "عرض الكل"
4. **شريط المنصات** المتحرك
5. **كيف يحلّل النظام السوق؟** — أربع خطوات على خط زمني

## قاعدة البيانات (Supabase)

كل المستخدمين يقرأون **نفس الصفوف** من نفس الجدول، وأي تغيير يصل لكل الأجهزة
المفتوحة في نفس اللحظة عبر البث اللحظي — لا توجد أي بيانات عشوائية في المتصفّح.

**المشروع:** `sigma-signals` · `oaqokzeysopcoiqdghef` · منطقة `eu-central-1`

### جدول `trades`

| العمود | النوع | ملاحظات |
|---|---|---|
| `id` | uuid | مفتاح أساسي |
| `pair` | text | الزوج أو الأداة |
| `market` | enum | `forex` / `binary` |
| `direction` | enum | `buy` / `sell` / `call` / `put` |
| `indicator` | text | المؤشّر الذي أعطى الإشارة |
| `outcome` | enum | `win` / `loss` — فارغة أثناء تنفيذ الصفقة |
| `status` | enum | `live` (البث المباشر) / `closed` (سجل النتائج) |
| `opened_at` / `closed_at` | timestamptz | الترتيب يعتمد عليهما |

قيد `trades_closed_needs_result` يمنع وجود صفقة مغلقة بلا نتيجة، أو صفقة جارية
لها نتيجة.

### الصلاحيات

RLS مفعّل مع سياسة **قراءة عامة فقط**. لا توجد سياسات `insert` / `update` /
`delete` إطلاقًا، فالكتابة حصرًا من الواجهة الخلفية بمفتاح `service_role`.
تم اختبار ذلك عمليًا من المتصفّح: القراءة تنجح، والإضافة تُرفض بـ
`new row violates row-level security policy`، والتعديل والحذف لا يمسّان أي صف.

### الإعداد

```bash
cp .env.example .env.local   # ثم املأ VITE_SUPABASE_URL و VITE_SUPABASE_ANON_KEY
```

لو المتغيّرات غير مضبوطة، يعمل التطبيق ببيانات محلية تجريبية بدل أن يتعطّل.

⚠️ لا تضع `service_role` في ملفات `.env` الخاصة بالواجهة — كل ما يبدأ بـ `VITE_`
يُحزَم داخل ملفات المتصفّح ويصبح مقروءًا لأي مستخدم.

## نظام الاشتراك

### الرموز

جدول `subscription_codes` — الرمز نفسه هو المفتاح الأساسي، فالتكرار **مستحيل**
على مستوى قاعدة البيانات لا على مستوى الكود. الصيغة: `pro` + ٨ محارف عشوائية
من حروف وأرقام ورموز، مع استبعاد المحارف الملتبسة (`l` و `1` و `0` و `o`).

`internal.redeem_code` يقفل صفّ الرمز بـ `for update` قبل قراءته، فلو حاول
شخصان استخدام نفس الرمز في نفس اللحظة ينجح واحد فقط.

| الحالة | النتيجة |
|---|---|
| رمز صحيح غير مستخدم | تفعيل + `subscription_expires = now() + 1 month` |
| نفس الرمز مرّة ثانية | `already_used` |
| رمز غير موجود | `not_found` |

### الانتهاء

مهمّة `expire-subscriptions` تعمل كل دقيقة وتحوّل `active` إلى `expired` عند
تجاوز التاريخ. الواجهة لا تكتفي بذلك: `useSubscription` تقارن بتاريخ الانتهاء
مباشرة كل ٣٠ ثانية، فيعود التمويه في اللحظة الصحيحة دون انتظار المهمّة.

### بوت الأدمن

Edge Function باسم `telegram-bot` تعمل كـ webhook. طبقتا حماية: سرّ الـ webhook
في ترويسة الطلب، والتحقّق من أن المرسِل هو `ADMIN_USERNAME`.

| الأمر | الوظيفة |
|---|---|
| `/new` | رمز جديد |
| `/new 5` | حتى ٢٠ رمزًا دفعة واحدة |
| `/list` | الرموز غير المستخدمة |
| `/stats` | إحصائيات الرموز والمشتركين |

### الأسرار المطلوبة

| المفتاح | القيمة |
|---|---|
| `TELEGRAM_BOT_TOKEN` | توكن البوت من BotFather |
| `ADMIN_USERNAME` | `VORTEXX_SUPPORT1` |
| `TELEGRAM_WEBHOOK_SECRET` | نصّ عشوائي من اختيارك |

## ملاحظة حول البيانات

الصفوف الحالية في الجدول **بيانات بذرة تجريبية** لبناء الواجهة. قبل النشر
للمستخدمين يجب استبدالها بسجل التداول الفعلي، وإبقاء نصّ إخلاء المسؤولية في
`MoreDialog.jsx`.
